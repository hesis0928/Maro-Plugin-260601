        
### **투 트랙 아키텍처 빌드 및 테스트 완료까지의 문제 해결 과정 요약**

#### **문제 A: CMake Python 버전 및 경로 충돌**
*   **발생 원인**:
    1.  시스템에 여러 버전의 Python(3.8, 3.12 등)이 설치되어 있어, CMake가 ROS 2 Humble이 요구하는 `3.8` 버전이 아닌 다른 버전을 먼저 탐색했습니다.
    2.  `python.exe`의 경로를 강제로 지정한 후에도, 해당 실행 파일이 필요로 하는 DLL(예: `python38.dll`)을 찾지 못하거나 다른 버전의 DLL과 충돌하여 인터프리터 실행에 실패했습니다.
*   **문제 해결**: CMake 구성 단계에서만 임시로 `PATH` 환경 변수를 조작하여, 지정된 Python 3.8의 경로가 다른 모든 경로보다 우선되도록 설정했습니다.

*   **a. 수정된 문서: `CMakeLists.txt`**
    *   **수정 방식**: `find_package(Python3 ...)` 명령어 이전에 `get_filename_component`와 `set(ENV{PATH} ...)`를 사용하여 Python 실행 파일이 위치한 디렉터리를 `PATH` 환경 변수의 맨 앞에 추가했습니다.
    *   **구조 및 원리**:
           # 1. 실행 파일의 전체 경로에서 디렉터리 부분만 추출
    get_filename_component(PYTHON_DIR ${Python3_EXECUTABLE} DIRECTORY) 
    
    # 2. 추출된 디렉터리를 기존 PATH 환경 변수($ENV{PATH})의 앞에 추가
    set(ENV{PATH} "${PYTHON_DIR};$ENV{PATH}") 
        
        
        이 방식은 운영체제가 프로그램을 실행할 때 필요한 DLL을 탐색하는 순서를 변경합니다. `C:/Program Files/Python38` 디렉터리를 최우선으로 탐색하게 만들어, 다른 경로에 있는 다른 버전의 Python DLL과 충돌하는 문제를 원천적으로 차단합니다.

---

#### **문제 B: CMake Python 개발 파일(Development) 탐색 실패**
*   **발생 원인**: Python 설치 자체는 완전했으나, CMake의 `find_package` 명령어가 `Development` 컴포넌트(헤더 및 라이브러리 파일)를 찾는 과정에서 지속적으로 실패했습니다. 이는 ROS 2와 vcpkg 환경이 복잡하게 얽혀 발생한 탐색 로직의 문제였습니다.
*   **문제 해결**: CMake의 자동 탐색 기능을 완전히 우회하는 방식을 채택했습니다. `find_package`에게는 가장 기본적인 `Interpreter`의 존재만 확인하도록 요청하고, 컴파일과 링크에 실제로 필요한 헤더와 라이브러리 파일의 경로는 수동으로 직접 지정해주었습니다.

*   **a. 수정된 문서: `CMakeLists.txt`**
    *   **수정 방식**:
        1.  `find_package`의 `COMPONENTS` 인자에서 `Development`를 제거했습니다.
        2.  `target_include_directories`를 사용해 Python 헤더 파일(`Python.h`)의 경로를 직접 추가했습니다.
        3.  `target_link_libraries`를 사용해 Python 라이브러리 파일(`python38.lib`)의 절대 경로를 직접 링크했습니다.
    *   **구조 및 원리**: 이 방식은 "CMake의 자동 탐색을 신뢰하지 않고, 개발자가 모든 것을 직접 제어한다"는 원리입니다. `find_package`의 역할을 최소화하여 CMake 구성 오류를 회피하고, 실제 빌드에 필요한 정보는 `target_*` 명령어를 통해 컴파일러와 링커에게 명시적으로 전달하여 모호함 없이 빌드를 성공시킵니다.

---

#### **문제 C: 링커 오류 LNK1104 (Maya 라이브러리 탐색 실패)**
*   **발생 원인**: `Foundation.lib`와 같은 Maya 라이브러리 파일이 올바른 Devkit 경로에 존재함에도 불구하고 링커가 이를 찾지 못했습니다. 이는 `ament_cmake` 빌드 시스템이 `link_directories`나 `target_link_directories`와 같은 표준 CMake 경로 탐색 명령어를 재정의하거나 방해했기 때문입니다.
*   **문제 해결**: 라이브러리 검색 경로를 지정하는 간접적인 방식 대신, 각 Maya 라이브러리 파일의 전체 절대 경로를 `target_link_libraries`에 직접 명시했습니다.

*   **a. 수정된 문서: `CMakeLists.txt`**
    *   **수정 방식**: `Foundation`과 같은 라이브러리 이름 대신 `"${DEVKIT_LOCATION}/lib/Foundation.lib"`와 같이 변수를 포함한 전체 파일 경로를 링크 목록에 추가했습니다.
    *   **구조 및 원리**: 이 방식은 링커에게 "이 폴더들을 검색해봐"라고 지시하는 대신, "이 경로에 있는 이 파일을 정확히 사용해"라고 직접 명령하는 것과 같습니다. 이는 빌드 시스템의 경로 설정에 의존하지 않는 가장 강력하고 확실한 링크 방식입니다.

---

#### **문제 D: 통합 테스트 환경 구축 및 의존성 오류**
*   **발생 원인**: 테스트 타겟(`ipc_integration_test`)을 `ament_package()` 명령어 뒤에 추가하여, ROS 2 빌드 시스템이 테스트 관련 설정을 인식하지 못했습니다. 또한, vcpkg를 통해 설치된 외부 라이브러리(OpenCV, GTest)를 테스트 타겟이 찾지 못하는 문제가 발생했습니다.
*   **문제 해결**: ROS 2 프로젝트의 표준 구조에 맞춰 `CMakeLists.txt`를 재구성했습니다. 모든 `find_package` 호출을 스크립트 상단으로 옮기고, 모든 타겟(주 플러그인, 테스트) 정의를 `ament_package()` 명령어 앞으로 이동시켰습니다. 또한, `OpenCV::opencv_core`와 같은 모던 타겟 대신, 시스템 충돌이 적은 레거시 변수(`${OpenCV_LIBS}`)를 사용하여 링크했습니다.

*   **a. 수정된 문서: `CMakeLists.txt`**
    *   **수정 방식**:
        1.  모든 `find_package` 호출을 스크립트 상단(2번 섹션)에 모았습니다.
        2.  테스트 타겟 정의(`if(BUILD_TESTING)`) 블록을 `ament_package()` 호출 앞으로 옮겼습니다.
        3.  테스트 타겟의 라이브러리 링크 방식을 모던 타겟에서 `${OpenCV_LIBS}` 변수를 사용하는 방식으로 변경했습니다.
    *   **구조 및 원리**: 이 구조는 CMake가 프로젝트의 모든 의존성을 초기에 파악하고, 모든 타겟을 정의한 후, 마지막에 ROS 2 패키지로 최종 등록하는 표준적인 절차를 따릅니다. 이는 빌드 시스템 간의 충돌을 최소화하고 예측 가능한 빌드 환경을 만듭니다.
*   **새롭게 사용된 명령어/방식**:
    *   `vcpkg install gtest:x64-windows`: C++ 유닛 테스트 프레임워크인 Google Test를 설치.
    *   `vcpkg install opencv:x64-windows`: 컴퓨터 비전 라이브러리인 OpenCV를 설치.
    *   `gtest_discover_tests()`: CMake가 빌드 시점에 테스트 실행 파일 안의 모든 테스트를 자동으로 찾아주는 기능.

---

#### **문제 E: 테스트 실행 런타임 오류 및 환경 설정**
*   **발생 원인**:
    1.  Visual Studio에 Google Test 확장 프로그램(Test Adapter)이 없거나 비활성화되어 '테스트 탐색기'가 테스트를 인식하지 못했습니다.
    2.  테스트 실행 파일이 의존하는 DLL(OpenCV, Boost 등)의 경로가 시스템 `Path`에 없어, 테스트 탐색기가 테스트 실행에 실패했습니다.
    3.  `Boost.Interprocess`가 공유 메모리를 생성하는 데 필요한 관리자 권한이 없어 "지정된 파일을 찾을 수 없습니다" 예외가 발생했습니다.
*   **문제 해결**: Visual Studio의 구성 요소를 설치하고, 시스템 환경 변수를 설정한 뒤, 최종적으로 Visual Studio를 관리자 권한으로 실행하여 모든 문제를 해결했습니다.

*   **a. 수정된 문서: 없음 (개발 환경 설정 변경)**
    *   **수정 방식**:
        1.  **Visual Studio 설치 관리자**를 통해 "Google Test용 테스트 어댑터" 구성 요소를 설치했습니다.
        2.  **시스템 환경 변수 `Path`**에 vcpkg의 `bin` 폴더 경로(`C:\src\vcpkg\installed\x64-windows\bin`)를 추가했습니다.
        3.  **Visual Studio를 관리자 권한으로 실행**하여 테스트를 최종적으로 통과시켰습니다.
    *   **구조 및 원리**: 코드뿐만 아니라 코드가 실행되는 환경(Runtime Environment)도 매우 중요합니다. 테스트 탐색기와 같은 IDE 기능은 필요한 확장 프로그램에 의존하며, C++ 프로그램은 런타임에 필요한 DLL을 `Path` 환경 변수를 통해 찾습니다. 공유 메모리와 같은 시스템 전역 객체는 보안을 위해 관리자 권한을 요구하는 경우가 많습니다. 이 모든 환경적 요소를 충족시켜 줌으로써 로직 테스트가 성공적으로 실행될 수 있었습니다.
